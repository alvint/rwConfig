# The `rwconfig` File

This is the reference for the file format. If you want a gentler introduction,
start with [Getting Started](getting-started.md).

The file looks like a Java `.properties` file with room for a type, a set of
allowed values, and a default. Every line is one of three things: a comment, a
a library setting, or a property declaration.

## Where the file is found

The library looks in this order and uses the first one it finds:

1. the command line argument `rw.config.path=<location>`
2. the system property `rw.config.path`
3. the environment variable `RW_CONFIG_PATH`
4. a file named `rwconfig` on the classpath
5. a file named `rwconfig` in the working directory

The first three take a [location](config-sources.md#locations), so the file can
live on the classpath, in a jar, or behind a URL, not just on disk.

> **Note:** the classpath is checked *before* the working directory. A file
> bundled in your jar wins over one sitting next to it.

## Comments

A line whose first non-whitespace character is `#` or `!` is a comment.

```
# a comment
    # also a comment, indentation is fine
! and this
```

Only at the start of a line. A `#` inside a value is part of the value.

## Declaring a property

```
<type>[<allowed values>] <name> = <default value>
```

Everything except the name is optional:

```
myProperty                                  a string, no default
myProperty = hello                          a string with a default
int myProperty = 8080                       an int with a default
int[80, 1024:65535] myProperty = 8080       an int, restricted, with a default
[home, work] myProperty = home              a string, restricted (type omitted)
```

A property with no default **must** be set by one of the [config
sources](config-sources.md), or startup fails. That is how you require
configuration without putting the value in a shared file.

### Types

`boolean`, `int`, `long`, `double`, `string`, and a list form of each:
`booleanList`, `intList`, `longList`, `doubleList`, `stringList`. Omitting the
type gives you `string`.

Booleans accept `true`/`false`, `yes`/`no`, `on`/`off`, `1`/`0`, in any case.

A type is only a type when a space or a `[` follows it, so a property may be
named `longitude` or `stringify` without its first few characters being taken
as a type. A property may even be named exactly `int`.

### Names

Names begin with a letter and may contain letters, digits, `.`, `_`, `-` and
`\`. Backslashes appear in names generated by the hierarchical plugins - a YAML
key `server.port` nested under `app` becomes `app\server.port`.

```
firstName        first-name        my.dotted.name        a\b
```

Two declarations of the same name are an error.

## Values

Leading whitespace around a value is dropped; trailing whitespace is kept.

```
string a =   hello           ->  "hello"
string b = hello             ->  "hello"
string c = hello             ->  "hello   "   (trailing spaces kept)
string d =                   ->  ""           (empty, which is a valid string)
```

To keep a leading space, escape the first one:

```
string e = \   indented      ->  "   indented"
```

### Escape sequences

| escape | meaning |
|---|---|
| `\\` | a literal backslash |
| `\e` | an empty string |
| `\n` `\r` `\t` | newline, carriage return, tab |
| `\uXXXX` | the character with that four-digit hex code |
| `\ ` | a space - **only** as the first non-whitespace character of a value |
| `\,` | a literal comma, so a list item can contain one |

Anything else - `\q`, `\[`, a malformed `\u12` - is an error.

`\ ` anywhere but the start of a value does nothing (a space needs no escaping
there), so it is almost always a mistake. The library logs a warning and treats
it as a plain space. The editor extension flags it as an error.

`\e` is genuinely useful for anything that would otherwise be ambiguous:

```
string empty = \e            an empty string, stated rather than implied
string noSpace = no\espace   "nospace" - \e joins the two halves
```

### Lists

Comma-separated. Whitespace after each comma is dropped.

```
intList ports = 1520, 8080          [1520, 8080]
stringList names = a, b, c          ["a", "b", "c"]
intList none =                      []  (an empty value is an empty list)
```

Only `stringList` may contain blank items, because only strings have a blank
value. Blank items come from adjacent commas or from `\e`:

```
stringList a = one,,two             ["one", "", "two"]
stringList b = , one                ["", "one"]
stringList c = one,                 ["one", ""]
stringList d = \e                   [""]      one blank item, not an empty list
stringList e =                      []        an empty list
```

A blank item in any other list type is an error. To put a comma inside a string
item, escape it:

```
stringList quotes = to be\, or not to be, seize the day
```

...is two items, the first containing a comma.

## Allowed values

A comma-separated list in square brackets, immediately after the type:

```
string[home, work, other] contactType = other
int [ 2, 3, 5, 7 ] prime = 3
intList[2, 3, 5, 7] primes = 3, 7
```

Every value - the default here and anything a source supplies later - must be
in the list. For list types, each item in the list must be allowed.

Allowed values must be the same type as the property. `int[a, b] x = 1` is an
error.

### Ranges

Any entry may be `<min>:<max>` instead of a single value. Ranges are inclusive
and work for numbers, strings (compared lexicographically), and booleans (where
they are of little use).

```
int[0:100] score = 90
intList[80, 1024:65535] ports = 1520, 8080      a value and a range together
string[0:9, A:F] hexDigit = 5
```

A range needs a value on both sides. `[:100]`, `[100:]` and `[0:10:20]` are all
errors. For an open-ended string range, use `\e` - the empty string sorts
before everything:

```
string[\e:z] anythingUpToZ = hello
```

### Escapes inside allowed values

Allowed values accept the same escapes as values, plus three that are needed
because those characters are meaningful inside the list:

| escape | for |
|---|---|
| `\]` | a `]` that should not close the list |
| `\,` | a `,` that should not separate values |
| `\:` | a `:` that should not make a range |

A `[` needs no escaping once the list is open, and cannot be escaped - `\[` is
not an escape sequence anywhere.

```
string[a\,b, c\:d, e\]f, g[h\]] punctuation = g[h]
```

...declares four allowed values: `a,b`, `c:d`, `e]f` and `g[h]`.

An escaped space is allowed as the first character of an allowed value, and
rejected anywhere else - here the parser enforces it rather than warning.

## Splitting long lines

A line ending in a backslash continues on the next line. The backslash is
removed and the lines are joined:

```
rwc.sources = args, system, environment, local, organization, \
              app, prefix, directory
```

This works anywhere: in a value, in a list, inside an allowed values list.

Two things to know:

- **Lines are joined before comments are removed.** A comment ending in a
  backslash swallows the line after it, which is rarely what you want:

  ```
  # this comment ends with a backslash \
  string myProperty = this line disappears into the comment
  ```

- **The test is a plain "does it end with a backslash".** A line ending in `\\`
  also continues, and leaves a trailing backslash behind, which is usually an
  invalid escape sequence.

## Library settings

Lines beginning with `rwc.` are *library settings*: they configure rwConfig
itself rather than declaring properties of your application. They never appear
in `getPropertyNames()` and your code cannot read them. They are covered in
[Config sources](config-sources.md).

All of them are optional. A file containing nothing but property declarations
is valid, and every property then takes its declared default.

If `rwc.` collides with a property name you need, change the prefix:

```
rwc.root = myapp.
myapp.sources = environment
myapp.environment.type = environmentVariables
```

`rwc.root` must be spelled exactly - `RWC.ROOT` is treated as an ordinary
property name.

## A complete example

```
# --- library settings ---
rwc.sources = args, local, environment

rwc.args.type = commandLineArguments
rwc.local.type = properties
rwc.local.location = file:app.properties
rwc.local.ignoreUnknownProperties = true
rwc.environment.type = environmentVariables

# --- the application's properties ---
appName = MyApp
int[80, 1024:65535] port = 8080
boolean debugMode = off
double samplingRate = 0.25
intList[1024:65535] workerPorts = 9001, 9002
string[dev, staging, prod] environment = dev
stringList features = search, export
string apiKey
```
